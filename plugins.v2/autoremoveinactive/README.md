# 种子自动删除 (AutoRemoveInactive)

自动删除下载器中长时间无活动的种子，以及所有 tracker 都失联的种子；当同下载器内存在其他文件路径重叠的种子（辅种）时，**仅删种不删文件**，避免影响其他辅种。

支持 qBittorrent 与 Transmission。

## 功能特性

- 跨下载器多实例支持
- 自动识别辅种：同下载器内若存在其他种子与待删种子的文件路径重叠，则只删种不删文件
- 标签白名单 / 黑名单过滤
- 自定义扫描周期与无活动阈值
- **Tracker 失联立即删除**：每次定时扫描拉取种子 tracker 状态，所有 tracker 都失联时跳过时间阈值立即删除
- 支持 qBittorrent 与 Transmission
- 通过 MoviePilot 的通知系统发送执行结果

## 配置项

### 基础配置

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启用插件 | bool | `false` | 是否启用本插件 |
| 发送通知 | bool | `true` | 执行完成后是否发送通知 |
| 保存后立即运行一次 | bool | `false` | MP 系统识别该字段，保存配置后立即触发一次执行 |
| 监控的下载器（多选） | list | `[]` | 选择需要扫描的下载器实例 |
| 定时 Cron（5 位） | str | `*/20 * * * *` | 定时扫描周期 |
| 通知渠道 | str | `插件` | 本插件发通知的渠道；选项来自系统已启用的通知渠道 |

### 无活动清理

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 删种阈值（分钟） | int | `30` | 超过此时长无活动的种子会被删除 |
| 无辅种时同时删文件 | bool | `true` | 是否在无辅种时同步删除文件 |
| 删文件阈值（分钟） | int | `30` | 仅在无辅种时生效；无活动超过此时长才允许同步删文件 |
| 只处理包含以下标签的种子 | str | `""` | 无活动清理的标签白名单 |
| 排除含以下标签的种子 | str | `""` | 无活动清理的标签黑名单 |

### Tracker 失联立即删除

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启用：所有 tracker 失联时立即删除 | bool | `false` | 与时间阈值无关，扫描时匹配即删 |
| 无辅种时同时删文件（默认只删种） | bool | `false` | 失联种子的默认行为是**只删种不删文件**；开启后才允许无辅种时同步删文件 |

> 标签过滤复用上方"无活动清理"区域的 `只处理包含以下标签的种子` / `排除含以下标签的种子`；两套清理共用同一组白/黑名单。

**Tracker 失联判断规则：**

- qBittorrent：通过 `torrents_trackers(hash)` 取所有 tracker；**全部** tracker 的 `status` 都 `!= 2`（Working）且 `!= 3`（Updating）时视为失联。空 trackers 列表视为该种子无 tracker 目标，**不在本功能处理范围**
- Transmission：通过 `torrent.tracker_stats` 取所有 tracker；**全部** tracker 的 `last_announce_succeeded=False` 且 `last_announce_result != 'Success'` 时视为失联。空 stats 同上跳过

### 通知渠道字段说明

本插件发通知时固定使用 `mtype=Plugin`（消息类型 = "插件"）。MoviePilot 的通知路由逻辑会把它发给所有 `switchs` 包含"插件"的渠道。

新增的 **通知渠道** 字段会在发通知时通过 `post_message(source=渠道名, ...)` 强制只发到所选渠道，跳过 switchs 匹配检查。即使用户在系统通知配置中没有为该渠道启用"插件"消息类型开关，本插件的通知也会被投递到该渠道。

- **默认值**：`插件`（即系统通知配置里名为"插件"的渠道）
- **选项**：动态拉取系统通知配置中所有已启用的渠道
- **兼容性**：所选渠道名若被禁用或删除，下次启动插件时会自动回退到 `插件`

## 适用场景

- **刷流种子批量清理**：配合 `只处理包含以下标签的种子 = 刷流` 标签白名单，只清理刷流产生的不活跃种子
- **个人辅种维护**：自动识别辅种关系，避免误删正在做种的内容
- **多下载器混合环境**：可同时监控 qBittorrent 和 Transmission
- **失联种子快速清理**：开启 `Tracker 失联立即删除` 后，每次扫描直接处理所有 tracker 都失联的种子；适合"tracker 死了但种子本身还想留一份"或"快速腾出 slot"的场景

## 注意事项

1. **删种阈值与删文件阈值分开配置**：删种阈值控制何时删种，删文件阈值仅在无辅种时控制何时允许同步删文件。两个阈值可以不同
2. **辅种判定基于文件路径重叠**：跨下载器不会互判辅种（不同下载器之间无法安全同步删文件）
3. **Transmission 标签支持有限**：需要在 MP 中已正确标记，复杂场景建议使用 qBittorrent
4. **通知渠道字段仅影响本插件**：不会影响系统其他模块或插件的通知路由
5. **删除后无法恢复**：建议先关闭"无辅种时同时删文件"，观察一段时间确认无问题后再开启
6. **Tracker 失联判定是单次扫描结果**：不做"连续 N 次失联"统计，每次扫描匹配到就立即删除；因此不建议在 `inactive_minutes` 很小（如 1 分钟）且网络抖动场景下同时开启 `Tracker 失联立即删除` 与 `无辅种时同时删文件`，以免把临时失联种子的文件误删
7. **空 tracker 列表不会被清理**：种子未填写 tracker 或在下载器中被识别为无 tracker 时跳过本功能

### v1.1.1

- Tracker 失联清理改为复用无活动清理的 `只处理包含以下标签的种子` / `排除含以下标签的种子`；去除冗余的独立配置项

### v1.1.0

- 新增 **Tracker 失联立即删除** 功能：每次定时扫描拉取每个种子的 tracker 状态，所有 tracker 都失联时跳过时间阈值立即删除
- 独立的白/黑名单标签过滤（与无活动清理互不影响）
- 无辅种时是否同步删文件可独立配置（默认只删种，最安全）
- 通知文案增加"tracker 失联清理"分项
- 统计与详情页增加失联删种/失联删文件计数（顶部 5 个统计卡 + 各下载器 chip + 最近运行表新增 2 列）

- 支持多下载器、跨种子 overlap 判定
- 标签白/黑名单过滤
- 通知 + 详情统计页
- 新增"通知渠道"配置项，可在插件配置中显式指定本插件的通知接收渠道
